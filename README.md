## 1. Описание проекта

**VFS Shell Emulator** — это эмулятор UNIX-подобной командной оболочки с виртуальной файловой системой (Virtual File System, VFS), содержимое которой загружается из ZIP-архива.

Программа предоставляет интерфейс командной строки, через который пользователь может просматривать каталоги, переходить между ними, читать файлы, подсчитывать характеристики файлов, выводить текст и выполнять другие операции.

Виртуальная файловая система представлена деревом объектов в оперативной памяти. ZIP-архив используется для первоначального заполнения этой структуры. Его содержимое не извлекается в обычную файловую систему компьютера.

Программа поддерживает два режима работы:

- **Интерактивный режим** — пользователь вводит команды по одной и сразу получает результаты.
- **Режим сценария** — программа последовательно выполняет команды из текстового файла и прекращает выполнение при первой ошибке.

Проект реализован на Python и использует стандартные библиотеки языка.

## 2. Цель и задачи работы

Цель работы — разработать командную оболочку, которая обеспечивает взаимодействие пользователя с виртуальной файловой системой и поддерживает выполнение основных файловых операций.

Для достижения цели необходимо выполнить следующие задачи:

- реализовать цикл REPL для ввода и выполнения команд;
- организовать вывод приглашения командной строки;
- реализовать разбор команд и их аргументов;
- добавить обработку переменных окружения;
- реализовать передачу параметров при запуске программы;
- обеспечить загрузку ZIP-архива в виртуальную файловую систему;
- реализовать разрешение путей к файлам и каталогам;
- добавить команды просмотра каталогов и перехода между ними;
- реализовать чтение файлов и подсчёт строк, слов и байтов;
- добавить создание каталогов и изменение владельца в метаданных VFS;
- реализовать справку и завершение работы;
- обеспечить выполнение команд из текстовых сценариев;
- реализовать обработку ошибочных ситуаций;
- подготовить автоматические тесты и документацию проекта.

## 3. Этап 1. Создание интерактивной оболочки REPL

### 3.1. Назначение этапа

REPL — это цикл взаимодействия с пользователем, название которого образовано от слов Read, Evaluate, Print, Loop.

Основная задача этапа — организовать постоянный цикл чтения команды, её обработки и вывода результата.

### 3.2. Принцип работы

При работе в интерактивном режиме программа выполняет следующие действия:

1. Формирует приглашение командной строки.
2. Ожидает ввода пользователя.
3. Разбирает введённую строку.
4. Определяет команду и её аргументы.
5. Находит обработчик соответствующей команды.
6. Выполняет команду.
7. Выводит результат или сообщение об ошибке.
8. Возвращается к ожиданию следующей команды.

Цикл продолжается, пока пользователь не выполнит команду `exit` или не завершит ввод.

### 3.3. Приглашение командной строки

Приглашение формируется методом `Shell.prompt()`.

Оно включает имя пользователя, имя компьютера, имя виртуальной файловой системы и путь текущего каталога.

Пример:

```text
user@computer:archive.zip:/$
```

Фактические значения зависят от окружения, имени ZIP-архива и текущего каталога.

Если переменные окружения `USER` и `USERNAME` отсутствуют, используется имя `user`. Если имя компьютера не удалось получить, используется `localhost`.

После перехода в другой каталог путь в приглашении изменяется.

### 3.4. Разбор команд

Метод `Shell.parse()` выполняет раскрытие переменных окружения и разбирает введённую строку с помощью `shlex.split()`.

Это позволяет использовать кавычки для объединения нескольких слов в один аргумент.

Пример:

```text
echo "Hello, world!"
```

Команда выводит:

```text
Hello, world!
```

Если кавычки не закрыты или строка не может быть корректно разобрана, программа сообщает об ошибке разбора команды.

Пустая строка не считается ошибкой и не приводит к выполнению какой-либо команды.

### 3.5. Обработка команд

Метод `Shell.execute()` определяет имя команды и вызывает соответствующий обработчик.

Обработчики реализованы методами класса `Shell`, названия которых начинаются с `cmd_`.

Например:

- `cmd_ls()` обрабатывает команду `ls`;
- `cmd_cd()` обрабатывает команду `cd`;
- `cmd_cat()` обрабатывает команду `cat`;
- `cmd_exit()` обрабатывает команду `exit`.

Если введена неизвестная команда, программа выводит сообщение об ошибке.

Ошибки команд обрабатываются через исключение `ShellError`.

### 3.6. Изменения в проекте на этапе 1

Основная логика оболочки находится в файле `src/main.py`.

В нём определены классы и функции, обеспечивающие работу оболочки:

- `ShellError` — исключение для ошибок команд и операций VFS;
- `Shell` — обработка команд и управление интерактивным циклом;
- `Shell.parse()` — разбор строки команды;
- `Shell.execute()` — выполнение команды;
- `Shell.prompt()` — формирование приглашения;
- `Shell.repl()` — запуск интерактивного режима.

На этом этапе формируется базовый механизм взаимодействия с пользователем, на который в дальнейшем опираются все команды.

## 4. Этап 2. Аргументы командной строки и выполнение сценариев

### 4.1. Назначение этапа

На втором этапе добавляется возможность управлять запуском программы через аргументы командной строки, а также выполнять заранее подготовленные последовательности команд.

### 4.2. Аргумент `--vfs`

Параметр `--vfs` задаёт путь к ZIP-архиву, который используется для создания виртуальной файловой системы.

Пример:

```bash
python src/main.py --vfs .test-vfs/full.zip
```

Если архив указан, программа загружает его содержимое в память.

Если параметр `--vfs` не указан, создаётся пустая виртуальная файловая система с именем `default-vfs`.

### 4.3. Аргумент `--script`

Параметр `--script` задаёт путь к текстовому файлу со сценарием команд.

Пример:

```bash
python src/main.py --vfs .test-vfs/full.zip --script scripts/minimal.txt
```

В этом случае программа загружает архив, открывает сценарий и выполняет команды последовательно.

Если параметр `--script` не указан, программа переходит в интерактивный режим.

### 4.4. Вывод конфигурации

Перед началом работы программа выводит информацию о параметрах запуска.

Пример:

```text
[config] vfs=.test-vfs/full.zip
[config] script=(интерактивный режим)
```

Если архив не указан, вместо его пути выводится:

```text
[config] vfs=(пустая VFS в памяти)
```

Если сценарий не указан, отображается `(интерактивный режим)`.

Конфигурация выводится при каждом запуске, в том числе при запуске без аргументов.

### 4.5. Правила выполнения сценария

Сценарий — это текстовый файл в кодировке UTF-8, содержащий команды оболочки.

Пустые строки и строки, начинающиеся с `#`, пропускаются.

Перед выполнением каждой команды сценария программа выводит приглашение и саму команду. Благодаря этому можно проследить последовательность выполнения.

Если команда завершилась ошибкой:

1. Выводится сообщение об ошибке.
2. Печатается сообщение о прекращении сценария с указанием файла и номера строки.
3. Следующие команды не выполняются.
4. Программа возвращает код завершения `1`.

Если команда `exit` успешно выполнена внутри сценария, выполнение завершается без перехода к последующим командам.

Если файл сценария невозможно открыть, программа сообщает об ошибке чтения и возвращает код `1`.

### 4.6. Изменения в проекте на этапе 2

В `src/main.py` добавлены функции:

- `parse_args()` — разбор параметров командной строки;
- `main()` — организация запуска приложения;
- `_print_config()` — вывод параметров запуска;
- `Shell.run_script()` — открытие и выполнение сценария;
- `Shell._run_script_lines()` — последовательная обработка строк сценария.

Для разбора аргументов используется стандартная библиотека `argparse`.

В проекте также предусмотрены файлы запуска `run.sh` и `run.bat`, позволяющие запускать программу из соответствующих операционных систем.

## 5. Этап 3. Реализация виртуальной файловой системы

### 5.1. Назначение этапа

На третьем этапе реализуется виртуальная файловая система, которая хранит файлы и каталоги в памяти и предоставляет методы для доступа к ним.

В отличие от обычной файловой системы, операции выполняются над внутренними объектами программы.

### 5.2. Класс `Node`

Класс `Node` представляет один узел виртуальной файловой системы.

Узел может соответствовать файлу или каталогу.

Основные поля:

- `is_dir` — признак того, является ли узел каталогом;
- `data` — содержимое файла в виде байтов;
- `owner` — имя владельца в метаданных VFS;
- `children` — словарь дочерних узлов каталога.

Для файла поле `data` содержит его содержимое, а для каталога используется `children`.

Владелец по умолчанию обозначается строкой `root`.

### 5.3. Класс `VirtualFileSystem`

Класс `VirtualFileSystem` отвечает за хранение и обработку виртуальной файловой системы.

Основные возможности класса:

- создание корневого каталога;
- загрузка ZIP-архива;
- добавление файлов и каталогов в дерево;
- разрешение путей;
- поиск узлов;
- просмотр содержимого каталога;
- изменение текущего каталога;
- создание каталогов;
- изменение метаданных владельца.

Корень VFS обозначается символом `/`.

Текущий каталог хранится в поле `cwd`.

### 5.4. Загрузка ZIP-архива

Метод `_load_zip()` открывает ZIP-архив для чтения и обрабатывает его элементы.

Метод `_add_archive_item()` добавляет каждый элемент архива в дерево виртуальной файловой системы.

Содержимое файлов читается в память. Архив не распаковывается в каталог операционной системы.

Если архив отсутствует, повреждён или не может быть прочитан, возникает `ShellError`, после чего программа выводит сообщение об ошибке загрузки VFS.

При такой ошибке запуск оболочки прекращается с кодом `2`.

Если в архиве встречается файл по пути, где промежуточный элемент должен быть каталогом, но уже является файлом, загрузка также завершается ошибкой.

### 5.5. Разрешение путей

Метод `resolve()` преобразует путь в последовательность компонентов дерева VFS.

Поддерживаются абсолютные и относительные пути.

Абсолютный путь начинается от корня:

```text
/docs/readme.txt
```

Относительный путь отсчитывается от текущего каталога:

```text
readme.txt
```

При обработке пути:

- пустые компоненты игнорируются;
- компонент `.` не меняет расположение;
- компонент `..` перемещает путь на уровень выше;
- переход выше корня остаётся в пределах корневого каталога;
- обратные косые черты преобразуются в прямые.

Если путь не существует или один из его промежуточных компонентов не является каталогом, программа сообщает об ошибке.

### 5.6. Просмотр и смена каталога

Метод `list_dir()` возвращает отсортированный список элементов каталога.

Если указанный путь ведёт к файлу, а не к каталогу, возникает ошибка.

Метод `change_dir()` изменяет текущий каталог. При попытке перейти к несуществующему пути или к файлу программа сообщает об ошибке и не меняет текущий каталог.

### 5.7. Изменение виртуальной файловой системы

Метод `mkdir()` создаёт каталог в памяти. Если такой элемент уже существует, операция завершается ошибкой.

Метод `chown()` изменяет поле `owner` выбранного узла.

Изменения не записываются в исходный ZIP-архив. Они существуют только в памяти текущего процесса и не сохраняются после завершения программы.

### 5.8. Изменения в проекте на этапе 3

В `src/main.py` реализованы классы:

- `Node` — узел дерева VFS;
- `VirtualFileSystem` — управление виртуальной файловой системой.

В класс `VirtualFileSystem` входят методы `_load_zip()`, `_add_archive_item()`, `_parts()`, `resolve()`, `node()`, `parent_and_name()`, `list_dir()`, `change_dir()`, `mkdir()`, `chown()` и `pwd()`.

Эти компоненты образуют основу для работы всех файловых команд.

## 6. Этап 4. Реализация основных команд

### 6.1. Назначение этапа

На четвёртом этапе реализуются основные команды, позволяющие взаимодействовать с виртуальной файловой системой.

К ним относятся:

- `ls`;
- `cd`;
- `cat`;
- `wc`;
- `echo`.

Каждая команда имеет отдельный обработчик в классе `Shell`.

### 6.2. Команда `ls`

Команда `ls` показывает содержимое каталога или имя указанного файла.

Синтаксис:

```text
ls [PATH]
```

Примеры:

```text
ls
ls /
ls docs
ls docs/readme.txt
```

Поведение:

- без аргумента показывает содержимое текущего каталога;
- при указании каталога выводит его элементы в алфавитном порядке;
- при указании файла выводит только имя файла;
- при указании несуществующего пути сообщает об ошибке;
- при попытке прочитать содержимое файла как каталога не выполняет операцию и сообщает об ошибке, если путь фактически ведёт к недоступному узлу.

Имена элементов каталога выводятся в одной строке и разделяются двумя пробелами.

### 6.3. Команда `cd`

Команда `cd` изменяет текущий каталог виртуальной файловой системы.

Синтаксис:

```text
cd [PATH]
```

Примеры:

```text
cd /
cd docs
cd ..
cd docs/manual
```

Поведение:

- без аргумента переводит пользователя в корень VFS;
- при указании существующего каталога меняет текущий каталог;
- относительный путь отсчитывается от текущего каталога;
- абсолютный путь отсчитывается от корня;
- `..` позволяет подняться на уровень выше;
- попытка перейти в несуществующий каталог приводит к ошибке;
- попытка перейти в файл приводит к ошибке;
- при ошибке текущий каталог не изменяется.

После успешного перехода обновляется путь, отображаемый в приглашении командной строки.

### 6.4. Команда `cat`

Команда `cat` выводит текстовое содержимое файла.

Синтаксис:

```text
cat FILE
```

Пример:

```text
cat README.txt
```

Поведение:

- принимает ровно один аргумент — путь к файлу;
- выводит содержимое файла, декодируя данные в UTF-8;
- если файл заканчивается символом новой строки, сохраняет это поведение;
- если файл не заканчивается новой строкой, добавляет её при выводе;
- если путь не существует, сообщает об ошибке;
- если путь ведёт к каталогу, сообщает, что это каталог;
- если файл содержит бинарные данные или данные, которые невозможно декодировать как UTF-8, сообщает об ошибке.

Команда не изменяет содержимое файла.

### 6.5. Команда `wc`

Команда `wc` подсчитывает характеристики файла.

Синтаксис:

```text
wc [-l|-w|-c] FILE
```

Если параметр режима не указан, выводятся все три значения.

Примеры:

```text
wc README.txt
wc -l README.txt
wc -w README.txt
wc -c README.txt
```

Поддерживаемые режимы:

| Режим | Назначение |
|---|---|
| Без параметра | Количество строк, слов и байтов |
| `-l` | Количество символов новой строки |
| `-w` | Количество слов |
| `-c` | Количество байтов |

Особенности подсчёта:

- строки считаются по количеству символов `\n`, а не по количеству визуальных строк;
- слова определяются разделением текста по пробельным символам;
- байты считаются по исходному содержимому файла, а не по числу символов;
- для подсчёта строк и слов данные декодируются с заменой некорректных последовательностей UTF-8;
- если путь не существует, выводится ошибка;
- если путь ведёт к каталогу, выводится ошибка;
- если аргументы не соответствуют синтаксису, программа выводит подсказку по использованию команды.

Результат содержит вычисленные значения и путь к файлу.

### 6.6. Команда `echo`

Команда `echo` выводит переданные аргументы, объединённые пробелами.

Синтаксис:

```text
echo [TEXT ...]
```

Примеры:

```text
echo Hello
echo Hello world
echo "Hello, world!"
echo
```

Поведение:

- выводит переданный текст;
- несколько аргументов объединяются пробелами;
- кавычки позволяют передать фразу как один аргумент;
- переменные окружения раскрываются перед обработкой команды;
- без аргументов выводится пустая строка;
- команда не создаёт файлы и не изменяет VFS.

### 6.7. Изменения в проекте на этапе 4

В `src/main.py` добавлены обработчики:

- `cmd_ls()` — просмотр каталога или имени файла;
- `cmd_cd()` — переход между каталогами;
- `cmd_cat()` — чтение текстовых файлов;
- `cmd_wc()` — подсчёт строк, слов и байтов;
- `cmd_echo()` — вывод текста.

Для единообразной проверки числа аргументов используется метод `_arity()`.

## 7. Этап 5. Реализация дополнительных команд

### 7.1. Назначение этапа

На пятом этапе добавляются команды для изменения виртуальной файловой системы, вывода справки и завершения работы.

К ним относятся:

- `mkdir`;
- `chown`;
- `help`;
- `exit`.

### 7.2. Команда `mkdir`

Команда `mkdir` создаёт новый каталог внутри VFS.

Синтаксис:

```text
mkdir PATH
```

Примеры:

```text
mkdir docs
mkdir /projects/new
```

Поведение:

- принимает ровно один аргумент;
- создаёт каталог по указанному пути;
- относительный путь отсчитывается от текущего каталога;
- абсолютный путь отсчитывается от корня VFS;
- родительский каталог должен существовать;
- если каталог или файл с таким именем уже существует, выводится ошибка;
- попытка создать каталог непосредственно в корне без имени запрещена;
- если родительский путь не существует или не является каталогом, операция завершается ошибкой.

Команда создаёт каталог только в оперативной памяти и не изменяет ZIP-архив.

### 7.3. Команда `chown`

Команда `chown` изменяет имя владельца в метаданных узла виртуальной файловой системы.

Синтаксис:

```text
chown OWNER PATH
```

Пример:

```text
chown student docs/report.txt
```

Поведение:

- принимает два аргумента: имя владельца и путь;
- ищет указанный файл или каталог;
- изменяет поле `owner` найденного узла;
- выводит сообщение об успешном изменении;
- если путь не существует, сообщает об ошибке;
- если число аргументов неверно, выводит подсказку по использованию команды.

Команда не меняет владельца физического файла операционной системы. Метаданные владельца существуют только внутри VFS в памяти программы.

### 7.4. Команда `help`

Команда `help` выводит список поддерживаемых команд и краткое описание их назначения.

Синтаксис:

```text
help
```

Поведение:

- не принимает аргументов;
- выводит справку по командам;
- при передаче лишних аргументов сообщает об ошибке использования.

Справка содержит следующие команды:

- `ls [PATH]`;
- `cd [PATH]`;
- `wc [-l|-w|-c] FILE`;
- `echo [TEXT ...]`;
- `cat FILE`;
- `mkdir PATH`;
- `chown OWNER PATH`;
- `help`;
- `exit`.

### 7.5. Команда `exit`

Команда `exit` завершает работу оболочки или прекращает выполнение сценария.

Синтаксис:

```text
exit
```

Поведение:

- не принимает аргументов;
- в интерактивном режиме завершает цикл REPL;
- в сценарии прекращает выполнение оставшихся команд;
- при передаче лишних аргументов сообщает об ошибке использования.

### 7.6. Изменения в проекте на этапе 5

В `src/main.py` реализованы обработчики:

- `cmd_mkdir()` — создание каталога;
- `cmd_chown()` — изменение владельца в метаданных;
- `cmd_help()` — вывод справки;
- `cmd_exit()` — завершение работы.

Также используется словарь `COMMAND_HELP`, содержащий краткие описания команд.

На этом этапе завершается реализация основного набора команд оболочки.

## 10. Описание команд и обработка ошибок

### 10.1. Сводная таблица команд

| Команда | Синтаксис | Назначение |
|---|---|---|
| `ls` | `ls [PATH]` | Вывод содержимого каталога или имени файла |
| `cd` | `cd [PATH]` | Изменение текущего каталога |
| `cat` | `cat FILE` | Вывод текстового содержимого файла |
| `wc` | `wc [-l|-w|-c] FILE` | Подсчёт строк, слов и байтов |
| `echo` | `echo [TEXT ...]` | Вывод текста |
| `mkdir` | `mkdir PATH` | Создание каталога в памяти |
| `chown` | `chown OWNER PATH` | Изменение владельца в метаданных VFS |
| `help` | `help` | Вывод справки |
| `exit` | `exit` | Завершение работы |

### 10.2. Неизвестная команда

Пример:

```text
unknown-command
```

Результат: программа выводит сообщение об ошибке с именем неизвестной команды.

В интерактивном режиме оболочка продолжает работу и ожидает следующую команду.

В сценарии неизвестная команда приводит к остановке сценария.

### 10.3. Неверное количество аргументов

Если команда получает больше или меньше аргументов, чем предусмотрено её синтаксисом, программа выводит подсказку по использованию.

Примеры:

```text
cat
mkdir
chown student
help extra
exit now
```

Такие вызовы не выполняют запрошенную операцию.

### 10.4. Несуществующий путь

Команды, которым требуется найти файл или каталог, сообщают об ошибке, если путь отсутствует.

Например:

```text
cat missing.txt
cd missing_directory
ls missing_directory
```

Ошибка не должна приводить к изменению текущего каталога или созданию отсутствующего объекта.

### 10.5. Попытка использовать файл как каталог

Если команда требует каталог, а указанный путь ведёт к файлу, операция завершается ошибкой.

Например, команда `cd` не может перейти в обычный файл.

### 10.6. Попытка прочитать каталог как файл

Команда `cat` проверяет тип узла. Если указанный путь ведёт к каталогу, программа сообщает, что это каталог.

Команда `wc` также не выполняет подсчёт для каталога.

### 10.7. Ошибки чтения содержимого

`cat` декодирует содержимое файла как UTF-8. Если данные являются бинарными или содержат некорректную последовательность UTF-8, команда выводит сообщение об ошибке.

`wc` использует декодирование с заменой некорректных последовательностей для подсчёта слов и строк, а количество байтов получает из исходных данных.

### 10.8. Ошибки создания каталога

Команда `mkdir` сообщает об ошибке, если:

- объект с таким именем уже существует;
- родительский каталог отсутствует;
- родительский путь ведёт к файлу;
- указанный путь соответствует корню VFS, для которого создание нового узла запрещено.

### 10.9. Ошибки ZIP-архива

Если ZIP-архив отсутствует, повреждён или недоступен для чтения, программа выводит сообщение о невозможности загрузки VFS.

В этом случае оболочка не запускается, а программа возвращает код завершения `2`.

### 10.10. Ошибки сценария

При первой ошибке сценарий останавливается. В сообщении указываются путь к сценарию и номер строки, на которой произошла ошибка.

Пустые строки и комментарии, начинающиеся с `#`, пропускаются и не исполняются.

## 11. Переменные окружения и обработка аргументов

### 11.1. Раскрытие переменных

Перед разбором команды выполняется раскрытие переменных окружения с помощью `os.path.expandvars()`.

Пример для UNIX-подобных систем:

```text
echo $HOME
```

Если переменная определена, её значение подставляется в команду.

Синтаксис переменных зависит от операционной системы и правил `os.path.expandvars()`.

### 11.2. Кавычки

Разбор команды выполняется с помощью `shlex.split()`.

Пример:

```text
echo "text with spaces"
```

Текст в кавычках передаётся как один аргумент. Сами кавычки не включаются в результат вывода.

### 11.3. Относительные и абсолютные пути

Абсолютный путь начинается от корня VFS:

```text
ls /docs
```

Относительный путь отсчитывается от текущего каталога:

```text
ls docs
```

Компоненты `.` и `..` обрабатываются при разрешении пути.

### 11.4. Отличие переменных окружения от файлов VFS

Переменные окружения берутся из окружения операционной системы, а файлы и каталоги — из виртуальной файловой системы.

VFS не предоставляет прямой доступ к произвольным файлам компьютера через свои команды: операции разрешения путей выполняются внутри дерева виртуальной файловой системы.

- относительные пути;
- абсолютные пути;
- обработку `..`;
- чтение файла по вложенному пути.

### 13.4. Изменения во время работы

Команды `mkdir` и `chown` позволяют проверить изменение внутренней структуры и метаданных VFS.

После создания каталога его можно увидеть с помощью `ls`. Изменение владельца выводит подтверждение операции, однако отдельная команда просмотра владельцев в текущем наборе команд не предусмотрена.

Изменения остаются в памяти программы и не записываются в ZIP-архив.


## 14. Работа с Git

Git используется для отслеживания изменений в исходном коде и документации.

### 14.1. Проверка состояния

```bash
git status
```

Команда показывает изменённые, добавленные и неотслеживаемые файлы.

### 14.2. Просмотр истории

```bash
git log --oneline
```

Команда выводит историю коммитов в сокращённом виде.

### 14.3. Просмотр изменений

```bash
git diff
```

Команда показывает изменения, которые ещё не были добавлены в индекс.

### 14.4. Добавление файла

```bash
git add README.md
```

Команда добавляет изменения README в индекс Git.

### 14.5. Создание коммита

```bash
git commit -m "Update README documentation"
```

Команда создаёт коммит с подготовленными изменениями.


## 15. Заключение

В ходе работы разработан эмулятор командной оболочки с виртуальной файловой системой, загружаемой из ZIP-архива.

Программа поддерживает интерактивный режим REPL, запуск с параметрами командной строки, выполнение сценариев, разрешение виртуальных путей и работу с файлами и каталогами в оперативной памяти.

Реализованы команды `ls`, `cd`, `cat`, `wc`, `echo`, `mkdir`, `chown`, `help` и `exit`. Предусмотрена обработка ошибок, включая некорректные аргументы, отсутствующие пути, ошибки чтения файлов и ошибки загрузки ZIP-архива.

Проект содержит автоматические тесты, вспомогательные сценарии, файлы запуска и документацию.

Реализация демонстрирует основные принципы построения командной оболочки, организации виртуальной файловой системы, обработки пользовательского ввода и тестирования программного обеспечения.
